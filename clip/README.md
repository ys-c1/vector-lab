# clip 逐刀账目

复现“两个窗口连着裁，结果和一次裁对不上，也不知道是哪一步偏的”。
每一刀之后的多边形和面积单独落盘，再用账目反推第一个窗口的有效区域，
和独立方法直接求出的区域比面积：相对偏差必须 ≤ 1e-6（面积差在百万分之一以内）。

## 跑一遍

```sh
make test          # 单元测试（含顺时针窗口、退化窗口、两刀 vs 一刀）
make verify        # 四组窗口序列 + 拒绝用例 + 故障注入，端到端跑一遍
```

`verify` 的产物全部在 `ledger-out/`（已 gitignore）：

```
ledger-out/
├── report.tsv                     每步一行的账目
├── summary.tsv                    每个序列的汇总
└── seq1_axis2/
    ├── steps/step00_poly.txt|_area.txt     输入基线
    ├── steps/stepNN_poly.txt|_area.txt     第 NN 刀之后的主体
    ├── eff/stepNN_poly.txt|_area.txt       第一个窗口按同一序列裁剩的
    │                                       有效区域（由账目反推）
    ├── direct/stepNN_poly.txt|_area.txt    独立方法直接求出的有效区域
    └── direct/stepNN_oneshot_poly.txt|_area.txt
                                            用反推区域一次裁主体
```

每步记录：主体面积、反推有效区域面积、直接区域面积、一次裁面积、
本步裁剪耗时 `clip_ms`、账目核算耗时 `check_ms`、两个相对偏差。

## 账目怎么记

设主体为 P，窗口依次为 W1…Wn。

- **主体账目**：`P_k = P_{k-1} ∩ W_k`，每步把 `P_k` 和 `area(P_k)` 落盘。
- **反推有效区域**：`E_1 = W1`，`E_k = E_{k-1} ∩ W_k`。由交集的结合律，
  `P ∩ E_k` 应当等于 `P_k`，所以 `E_k` 就是第一个窗口在这串窗口里真正生效的区域。
  它也是“如果只用一个窗口一次裁完，该用哪个窗口”的答案。
- **直接区域**：把 W1…Wk 当普通凸多边形，用另一套算法（顶点候选 + 边交点 +
  凸包，不走 Sutherland–Hodgman）求 `W1 ∩ … ∩ Wk`。这是与账目独立的一路。

两个检查逐步骤做，任一步超差就停并打印步号：

| 检查 | 含义 |
|---|---|
| `rel_seq_vs_oneshot` | 连续裁剪的主体面积 vs 用 `E_k` 一次裁出的面积 |
| `rel_eff_vs_direct` | 反推区域面积 vs 独立直接求出的区域面积 |

容差 `1e-6` 是相对偏差（`|a-b| / max(|a|,|b|)`）；输出同时给了 ppm 值。
两路都用同一套 `double` 几何，实际偏差在 1e-16 量级；`1e-6` 是判据上限。

## 输入格式

```sh
./build/ledger plan <plan.txt> <outdir>
```

`plan.txt` 每行 `<序列名> <多边形文件> <窗口清单>`，路径相对 plan 所在目录：

```
seq1_axis2 poly_hex.txt seq1.txt
```

窗口清单每行 `<窗口号> <窗口文件>`，路径相对清单所在目录；窗口文件每行 `x y`：

```
101 win_1a.txt
102 win_1b.txt
```

## 拒绝规则

| 情况 | 退出码 | 报错 |
|---|---|---|
| 窗口文件为空 | 2 | `第 N 个窗口（窗口号 X）为空` |
| 窗口顶点不足三个 | 2 | `第 N 个窗口（窗口号 X）顶点不足三个（实际 K 个）` |
| 窗口号重复 | 2 | `第 N 个窗口（窗口号 X）与第 M 个窗口窗口号重复` |
| 窗口退化 / 非凸 | 2 | `第 N 个窗口（窗口号 X）退化或不是凸多边形` |
| 主体多边形不足三个顶点 | 2 | `序列 ... 主体多边形顶点不足三个` |
| 账目对不上 | 3 | `账目对不上：序列 S 第 N 步（窗口号 X）…` |

账目对不上时 `report.tsv` 会保留到失败步为止，`summary.tsv` 该序列记 `FAILED`。

## 四组序列（`tests/gen_ledger.py` 生成）

| 序列 | 内容 |
|---|---|
| `seq1_axis2` | 7 顶点主体，两个轴对齐窗口，两刀 |
| `seq2_rot120` | 120 顶点主体，两个旋转窗口，两刀（旧实现 64 点缓冲会截断） |
| `seq3_three` | 三角形主体，三个窗口，三刀 |
| `seq4_cw` | 8 顶点主体，第一刀顺时针窗口，第二刀旋转窗口 |

## 修掉的旧实现问题

1. **顺时针窗口把内部裁掉**：旧代码假定窗口逆时针，CW 窗口直接产出空多边形，
   一刀和两刀因此对不上。现在按有符号面积归一化方向。
2. **空区域沿用陈旧数据**：输入多边形已经裁空时，旧实现仍拿上一轮的多边形继续
   （调用方也容易这么做）。现在空输入面积记为 0，账目照常记录。
3. **超过 62 个顶点静默截断**：旧 `CPoly pts[64]` 写满即丢点且不报错。现在容量
   显式给到 `CLIP_MAX_VERTS`，超限返回 `-3`。
4. **退化窗口无检测**：零面积或相邻顶点重合的窗口现在返回 `-2`；驱动在装载
   窗口时就拒绝并报第几个窗口。

## 文件

| 文件 | 作用 |
|---|---|
| `src/clip.c|.h` | 裁剪实现（方向归一化、显式容量、退化检测） |
| `ledger.c` | 逐刀账目驱动：落盘、反推有效区域、独立直接求交、计时 |
| `test.c` | 单元测试 |
| `tests/gen_ledger.py` | 纯 Python 生成四组序列与拒绝用例 |
| `tests/fault_clip.c` | 故障注入：第 N 次裁剪输出微缩，验证账目能停在正确的步 |
| `verify.sh` | 端到端脚本 |
