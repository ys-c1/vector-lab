# palette

聚类定调色板。旧方案是手挑的 8 色表 + 最近邻量化，暗部只有 `#303030` 一档，
暗区 0..52 全被拉成一块。新方案把像素当 RGB 点做 k-means，按组内平方误差
最小化迭代中心，收敛后取整并做整数中心精修，得到每组的代表色。

## 用法

```
palette gen    <dir>             生成四类图 + 单色图（确定性 LCG，无外部依赖）
palette solve  <in> [k]          单图聚类，默认 k=8
palette batch  <manifest> [k]    清单每行 name path
palette legacy <in> <out.ppm>    旧逻辑：手挑 8 色最近邻量化
```

输入接受 PGM P5 / PPM P6（maxval=255）。

## 算法

1. **初始化**：取离加权均值最近的实际像素作为第一个中心，再按 maximin
   （离已选中心最远者）逐个补到 k 个；距离平局取 RGB 字典序小者。
2. **Lloyd 迭代**：每个像素分到最近中心（浮点质心，平方欧氏），再取组内均值；
   收敛判据是分配不再变化，轮数上限 256。
3. **整数化**：浮点质心四舍五入到 `[0,255]`，再做整数中心精修——每组取组内均值
   再取整，直到稳定。代表色因此是整数格点上的均值不动点，报表里的代表色与方差
   自洽。精修后重合的中心去重，组数只减不增。
4. **度量**：组内方差 = 组内平方误差总和 / 组内像素数（RGB 欧氏距离平方，未归一）；
   总方差 = 总平方误差 / 总像素数。对照组是手挑色表下的最近邻方差。

## 拒绝与单独报告

| 情况 | 状态 | 退出码 |
|---|---|---|
| k <= 0（组数为零） | `REJECT K-ZERO` | 4 |
| k > 32（超过上限） | `REJECT K-TOO-BIG` | 5 |
| 空图（无像素） | `REJECT EMPTY` | 3 |
| 全图只有一种颜色 | `SINGLE-COLOR`，组数 1、方差 0、不迭代 | 6 |
| 方差未比手挑低三成 | `target(reduce>=30%)=MISS` | 8 |

批量模式下取最坏退出码；单色图的 6 属于单独报告，不抬高批量退出码，其余条目照常评测。

唯一色不足 k 个时（例如 k=32 但图上只有 2 种颜色）不报错：实际组数就是非空组数，
报表里的 `groups=` 是实际值。

## 旧逻辑逐字节一致

`make check-legacy` 用 `tool.c` 里**独立冻结**的手挑实现生成基线，再用当前
`palette legacy` 重算，逐字节比对 PPM 全文件（含头）。基线同时落在
`baseline/` 目录里：

```
make check-legacy   # record 基线 → legacy 重算 → check 逐字节
```


## 实现要点

- **确定性**：初始化顺序、距离平局、质心取整都按固定规则；除 `elapsed_ms` 外
  输出逐字节可复现。
- **整数代表色自洽**：报出的 `rep` 就是整数格点上的组均值不动点；`var` 用这些代表色
  重新统计得到，不是浮点迭代的中间值。
- **k 大于唯一色数**不报错，按实际非空组数报告。
- **P_EMPTY** 用于 0 像素图；CLI 在加载后单独拦截，报 `REJECT EMPTY`（退出码 3）。
