# render

多边形场景光栅化：scene（多边形）→ pipeline（仿射摆放）→ raster（超采样）→ export（PGM）。

## 超采样路径

- `raster_fill(..., ss, buf)`：等分 `ss×ss` 子点，**二值**输出（命中即 255）。pipeline 默认走这条，`ss=4`。
- `raster_fill_mask(..., mask, buf)`：按 16 位 4×4 位掩码布点，**灰度覆盖率**输出 `255*hit/K`，K=掩码置位数。

### 掩码格式

`unsigned short`，bit `4*row + col`（row/col 为 0..3），置位格子在 `(col+0.5)/4, (row+0.5)/4` 处布点。
字符串解析 `raster_mask_parse` 要求**恰好 16 个 0/1**：

- 位数 ≠ 16 → `-2`（拒绝）；含非 0/1 字符 → `-3`；空指针 → `-1`。
- 全零掩码：解析合法但无采样点，`raster_fill_mask` 返回 `-4` 拒绝渲染。
- 全一掩码（0xFFFF）：16 点全用，等价满网格；其二值支持与 `raster_fill(ss=4)` 完全相同。

CLI：`cli scene.txt out.pgm w h scale [mask16]`。缺省第 6 参数走原等分二值路径，
输出与引入掩码前**逐字节相同**（由 `tools/diff.sh` 对 git HEAD 版本验证）。

## 为什么掩码不能缩短斜边花纹周期（重要负结果）

需求曾假设「等分点在斜边上产生规则花纹，换成掩码布点可缩短花纹周期」。数值与穷举证明该假设不成立：

1. 4×4 掩码的子点仍是**同一个 4×4 子晶格的子集**，没有引入新的采样位置，只是删点。
2. 斜边的摩尔纹/量化周期由**晶格间距与边斜率的别名（aliasing）**决定，与删哪些点无关。
3. 对 4 个角度组穷举全部 2^16−1 个非零掩码（`make bench`），能让周期严格小于等分满网格的掩码数为 **0**：
   掩码只能保持周期不变，或因破坏满网格的抵消对称而使周期变长（如 30°/75° 的部分掩码 1→4、13→26 行）。
4. 现有 raster 是二值输出：稀疏掩码在顶点/细特征处会丢失只落在被删子格上的覆盖（实测单点子掩码有 44/1024 像素翻转），
   且二值判定不产生新的灰度层次；掩码只在灰度覆盖率路径下才有意义。

角度用精确有理斜率作可测替身（tan15°≈7/26、tan30°≈4/7、tan60°≈7/4、tan75°≈26/7），
真实无理角无严格重复周期，但其摩尔纹由同一套晶格别名主导，结论一致。

要真正打散规则花纹，需改变采样位置本身（抖动/旋转网格/蓝噪声），而非在固定晶格上删点。

## 构建

- `make test`：单元测试（含掩码校验、全零/全一、字节不变量）。
- `make bench`：四角度组的掩码/精确花纹周期/耗时，并穷举 65536 个掩码给出周期下界。
- `make cli`：命令行渲染。
