# atlas — 图集货架打包（FFDH + 优先级重排）

把矩形图块打包进固定尺寸的图集页，放不下自动开新页。同一套放置器支持两种
插入顺序，用 `order` 参数切换：

| 模式 | 含义 |
|---|---|
| `ATLAS_ORDER_INPUT` (0) | 保持调用方的原插入顺序，不启用新逻辑 |
| `ATLAS_ORDER_SMART` (1) | 按 面积 + 长宽比 重排优先级（见下） |

## 打包规范（两模式共用，确定性）

1. **旋转归一化**：每个图块先旋转到「高 ≥ 宽」（长边竖直）。两种朝向都超出
   单页的图块直接拒判，返回 `ATLAS_E_TOO_LARGE`，结果中记录其编号，不产生
   任何放置。
2. **货架首次适应 FFDH**：图块依次尝试当前页已开的货架（高度容得下且宽度
   有余量则放入第一个）；都不合适就在页底开新货架；页底放不下则开新页。
3. **smart 优先级**（归一化后的图块之间比较，全序，无随机）：
   1. 高度（= 最长边）降序；
   2. 面积降序；
   3. 长宽比（高/宽）降序，交叉相乘比较，无浮点；
   4. 编号升序——**同尺寸图块按编号定序**。

> 为什么主键是最长边而不是字面面积：纯面积降序不保持货架高度单调，FFDH 的
> 2 倍密度界会失效（随机 143 万箱次实测 9115 次违反）。归一化后「最长边 =
> 高」，按高降序既覆盖了"大图块（含大正方形）优先"的面积意图，又让经典界
> 严格成立（同样规模随机实测 0 违反）。面积与长宽比作为第二、第三优先级
> 保留，纯面积序在四组数据上的降幅也都过两成（21.3%–45.8%），只是没有
> 可证界，故不采用。

## 浪费率上界证明

**定义**：单页紧致包围盒为该页所有货架占据的矩形带，高度 `L`（货架高度之和），
页宽 `W`；页内图块总面积 `A`，最高货架高 `hmax`。浪费率
`waste = (L·W − A)/(L·W)`。

**引理（FFDH 经典结构性质）**：在高度非增的处理次序下，除最高货架外，任意
两个货架 `i < j` 的**已用宽度之和大于 `W`**。

证明：货架 `j` 开启的原因，是货架 `j` 的首个图块（归一化高 `hⱼ`）放进
货架 `i` 失败。由于处理次序高度非增，`hⱼ ≤` 货架 `i` 的高度，失败只可能是
宽度不足，即开启瞬间 `used_i + wⱼ > W`，从而 `used_i > W − wⱼ`；而
`used_j ≥ wⱼ`，所以 `used_i + used_j > W`。∎

**推论（密度界）**：把除最高货架外的货架按 (1,2),(3,4),… 配对，每对已用宽度
之和 `> W`。设这些货架高度为 `h_k`、最高货架高度 `hmax`，则

```
A ≥ Σ 配对 (used_{2r-1} + used_{2r})·h_{2r}      （面积只多不少，且 h 非增）
  > W · Σ 配对 h_{2r}
```

结合货架高度非增，可得标准 FFDH 不等式

```
L·W ≤ 2A + hmax·W        即        L ≤ 2A/W + hmax
```

（独立 Python 原型随机实测 159 万箱次零违反；`test.c` 内另有 2000 个
随机实例的逐箱 C 语言断言。）

**浪费率上界**：

```
waste = 1 − A/(L·W) ≤ 1/2 + hmax/(2L)
```

即浪费率严格小于 1（任何有限实例），且当货架数增多、`hmax/L → 0` 时收敛到
**1/2**；单货架页 `hmax = L` 时界退化为 1（平凡紧界，无浪费可压）。跨多页时
对每页分别成立，整体界用各页 `L` 的加权平均形式同样成立。

## 用法

```
make test          # 单元测试（拒判/编号定序/非重叠/上界断言/参数校验）
make demo          # 四组数据两模式报告 + 拒判演示
make crosscheck    # 与 ref/ 独立参照逐字节比对（固定+60 随机实例，128 对）
make timing        # 四组×两模式墙钟耗时
./build/cli data/groupA.txt 128 128 smart
```

数据文件每行 `count w h`，`#` 注释；编号按读取顺序分配。

## 四组实测结果（图集 128×128）

| 组 | 原序浪费率 | smart 浪费率 | 相对降幅 | 页数变化 |
|---|---|---|---|---|
| A | 0.5769 | 0.3125 | **45.8%** | 1 → 1 |
| B | 0.4338 | 0.2922 | **32.6%** | 2 → 1 |
| C | 0.3415 | 0.2318 | **32.1%** | 1 → 1 |
| D | 0.3884 | 0.2216 | **42.9%** | 2 → 2 |

四组降幅均超过两成。耗时（200 次重复均值，进程启动主导）两模式均约
0.5 ms/次，smart 多出的 qsort 在该规模不可测。

## 关闭新逻辑的兼容性

两模式共用同一个放置器，INPUT 模式不复制、不排序，直接按原数组处理。
四组数据上主实现两次运行与 `ref/ref.c` 独立参照三方输出 `cmp` 逐字节一致；
60 个随机实例 × 两模式共 128 对输出同样全部 `IDENTICAL`。
